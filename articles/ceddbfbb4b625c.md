# 記載スタイル
- 1行は72文字まで．
- 複数行の場合は空行を挟む．
- docstringと対象定義の間に空行を挟まない．
- モジュール:
	- `import`文の前に，公開するクラス・関数などを1行の説明をつけて一覧化
- クラス:
	- 何をするクラスなのかの概要，外部に公開するメソッドやインスタンス変数などを記述する
	- 冒頭ではdocstringとの間に空行を挟む
- 関数
	- 何をするのかの概要，パラメータ，戻り値，発生する例外などについて記述する

基本的には以下の形
```Python
"""概要(1行の文)

詳細な説明(複数行)

Note:
	なんでも
Todo: (あれば)
	- hoge
"""
```

# モジュール
ファイルの先頭に内容と用法を説明する．
```Python
"""概要(1行の文)

詳細な説明(複数行)
公開するクラス・関数などについて1行の説明を付けて一覧化する

"""
```

# テストモジュール
テストの実行方法に関する具体的な説明、珍しい設定パターンの説明、外部環境との依存関係などを書くが，必須ではない

# 関数
- 公開APIに含まれている，非自明なサイズ，明らかでないロジックな関数は必ず書く．
- 関数の呼び出し構文とその意味を記述する．
- オーバーライドしているメソッドについてはその旨を記すだけでよい．

セクションは以下
```Python
def func(
	param1: type1,
	param2: type2,
	...
) -> typeR:
	"""概要

	詳細な説明

	Args:
		param1: 説明1
		param2: 説明2
		...

	Returns: (or Yields: ジェネレータの場合)
		戻り値の型と説明

	Raises:
		例外1: 説明1
		例外2: 説明2
		...
	"""
```
- 関数名とシグネチャが十分なら省略してよい
- 各セクションは`名前:`と説明の間で改行してもよい
- `Args`について
	- 引数に型指定を入っていなければ`param1 (type1)`のようにする
	- `*foo`で可変長の引数リスト，`**bar`で任意のキーワード引数を表す
- `Returns`(`Yields`)について
	- `None`を返すなら不要
	- tupleを返すときは"A tuple (mat_a, mat_b)が返され，mat_aは...，mat_bは..."のように書く．
# クラス
publicの属性を持つ場合は以下のように記述する．
```Python
class hoge:
	"""概要

	詳細な説明

	Attributes:
		attr1: 説明1
		attr2: 説明2
		...
	"""
	
	def __init__(self, param: type = fuga):
		"""概要

		Args:
		  param: 説明
		"""
```
