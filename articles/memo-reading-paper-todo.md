# 読む前

1. 読む論文を決める（[参考](https://joisino.hatenablog.com/entry/2023/04/10/170519#-%E8%AB%96%E6%96%87%E3%81%AE%E9%81%B8%E3%81%B3%E6%96%B9)）
	- 積読リストから優先度高いもの
	- 自分の興味に関係するものをawesomeリストやproceedingsから探す
	- 国際会議や年でフィルタして、被引用数が多いものを選ぶ
	- サーベイ論文・チュートリアルから選ぶ
	- 推薦システム (Google Scholar, Semantic Scholar, Scholar Inbox) を使う
2. Zoteroに読み込む・タグづけ
3. plamoで翻訳をかける
4. Obsidianでメモのテンプレを生成する

# 読む

- 1週目: サーベイならここまで（5〜10分）
	- タイトルを見る
	- abstractを読む
		- 骨格（問題・手法・結果）をつかむ
	- introductionを読む
		- 背景（大・小）は何か？
		- 既存手法の何がだめか？
		- 問題設定（定義・入出力）は何か？
		- 目的は何か？
		- どういうアイデア・仮説か？
	- 見出しを追う
		- どんなロジックか？
	- conclusionを読む
		- どんな主張か？
		- どういう理由か？
	- 5つのCを整理する
		- Category: どういう種類の論文？(何かを測定したのか、もうあるものを分析したのか、研究用に作ったツールの説明なのか)
		- Context: それと関連のある他の論文には何があるか？課題解決の根底にある理論は何か？
		- Correctness: 論文内の仮定、仮説は正しそうか
		- Contributions: その論文があると何ができるようになるのか？
		- Clarity: ちゃんとした書き方がされているか
	- 最終的には「何が問題で何を主張しているか」を理解する
	- 読み進めるか判断する → 進めるなら2週目
		- 面白いか？面白くないならなぜか？
		- Future worksが取り組みやすそうか？
- 2週目: 関連研究に使う・専門でないならここまで（1時間）
	- 本文を注意深く読む
		- 重要事項をメモ
		- 分からない箇所をメモ
		- 重要そうな文献をメモする
	- 実験・図表をしっかり見る
		- どんな設定か？
			- 全体の流れ
			- タスク
			- データセット
			- 評価指標
			- 比較対象
		- どんな数値が出たか？
		- 主張とどんな関係か？（1つの図表に1つのメッセージ）
		- 不備がないか？
	- 以下をチェックする
		- 重要な未解決の問題は何か？
		- この論文で扱っていない問題のヒントがないか？
		- limitation / future work は何か？
		- related workでまだ誰も組み合わせてないものはないか？
	- 最終的には「実験内容と主張の根拠」を理解する
	- 読み進めるか判断する
		- 今後この論文には触れない or 背景知識をつけてから戻ってくる → メモ執筆 (brief)
		- 3週目に行く
- 3週目: 手法として使うならここまで（1時間程度～）
	- 精読する
		- 著者と同じ仮説を立てて、内容を再現する
		- 論文のどこが良いか？
		- 論文のどこが弱いか？
		- 抜けている主張・実験・引用はないか？
	- 今後の研究で何ができそうか？
		- 主張をどう批判できるか？
		- 手法はどう使うのか？
		- 新たなアイデアがあるか？
	- 関連研究を調べる（必要に応じて）
	- 最終的には著者の仮説・実験を再構成して批判できるようになる
- メモ執筆 （LLMを頼ってもよい。30分～）
	- brief
		- どういう問題か
		- どんな手法か
		- どういう結果か
		- 感想・自分との関連
	- full
		- 要約（どんな問題にどんな手法を使ってどういう結果が出たのか）
		- 背景（大・小）
		- 問題設定（定義・入出力・目的）
		- 既存手法
		- アイデア・仮説
		- 提案（手法の流れなど）
		- 実験設定
		- 実験結果・主張
		- 貢献・新規性
		- 限界・今後の課題
		- 感想・わからなかったこと・自分との関連

# 詰まったら

- 興味のあるものを読む
- 短いもの・簡単なものをちょっとずつ読む
- 長い・難しい箇所はLLMに聞く or 飛ばす
- 問いを持ちながら読む
- 要約を作る
- 音読する
- 場所を変える
- 時間を測る（読みやすさの指標になる）
