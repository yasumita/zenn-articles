# [Machine Theory of Mind Needs Machine Validation](https://aclanthology.org/2025.findings-acl.951/) (ACL Findings 2025)
Authors: Adil Soubki, Owen Rambow

- 言語モデル (LM) の心の理論 (ToM) を測るベンチマーク16個を調べたポジションペーパー
	- LM だけが利用しうるデータ内のパターンを確認する検証 (machine validation) を行っていない論文が多く、特に LM が人間を上回ると示した研究ではどれもこの検証をしていない
	- 一部のデータセット (SimpleToM, BigToM) では、小さいLMを fine-tuning するだけでほぼ満点に達することを示し、人間による検証だけに頼ったベンチマーク作りに注意を促している
- 背景
    - ToM は、他者の信念・意図・感情などの心的状態を推論する能力
    - Sally-Anne 課題などを模した質問応答形式のベンチマークが多数作られたが、例えばFANToM では「ToM はほぼない」、SimpleToM や MoToMQA などでは「人間並み・人間超え」とされるなど、結果は食い違っている
    - ToM-bAbi や ToMi のようなテンプレート型データでは、モデルが表層的な手がかりで正解してしまう問題がある
    - zero-shot 評価が重視されるにつれて、fine-tuning のベースラインを報告する研究が減っている
- machine validation
    - machine validation（機械だけが利用しうるデータ内のパターンを確認する検証）により、ベンチマーク上の性能が機械特有の疑似相関の利用によるものでないことを確かめる
    - 方法は2種類
        - 表層的手がかりの利用を検出できる仕組みを設計段階で組み込む（例：答えられない問題を混ぜる）
        - 作成後にデータ中の疑似相関を事後的に分析する
            - 小型モデルを fine-tuning したものをベースラインとする。人間は表面的なパターンに頼らないと考えられるので、単純なモデルの性能が非常に高ければ、疑似相関があるか課題が相対的に易しいことが示唆される
- メタ分析
    - 方法
        - ACL Anthology と Google Scholar で検索し、ToM 評価用のデータセットを提案した16本を選んだ
        - 各データセットについて記録した項目：最良モデルの zero-shot / few-shot / fine-tuning 性能、人間の性能、少なくとも1つの指標で LM が人間を上回ったか、認知的 ToM か感情的 ToM か、モダリティ、観察者か参加者か、回答形式、作成元、サイズ![](https://static.zenn.studio/user-upload/b5077e45cbd0-20261112.png)
            - 人間ベースラインがないデータセット（Hi-ToM, Adv-CSFB, ExploreToM, SimpleToM）では、人間超えかどうかを類似課題から著者らが推定している
	- 結果
	    - データを LM が生成したか人間が作ったかと、モデル性能との間に強い相関は見られなかった
	    - 誤信念以外の課題を扱うものも増えている（ToMBench, EPITOME, SimpleToM など）
	    - モデルを対話の参加者として評価するのは MindCraft のみ。テキスト以外の入力を含むのは3本、感情面を扱うのは4本
	    - 表層パターンや疑似相関の危険性に触れる論文は多いが、それを特定・修正する検証ステップを行ったのは OpenToM のみ
	    - 人間超えを報告したもの（EPITOME, BigToM, Strachan et al., MoToMQA, SimpleToM）は、いずれも語彙の重なりの計算や fine-tuning ベースラインといった検証を行っていない。
		    - 逆に、検証を行ったベンチマークでは人間以上の性能を報告したものはない
- ケーススタディ
    - 仮説：人間超えを報告したデータセットでは、fine-tuning しても高い性能が出る。
    - 対象：人間超えなしの FANToM と Common-ToM、人間超えありの SimpleToM と BigToM
    - モデル：BERT-base, GPT-2, Flan-T5-base を分類器として fine-tuning
    - 評価：Common-ToM は既存の分割で3シード、他は5分割交差検証の平均。
    - 補足：FANToM は自由記述問題を除外した。SimpleToM は同じシナリオが訓練とテストにまたがらないように分割した。
    - 結果：![](https://static.zenn.studio/user-upload/56d7f0b71fb3-20261112.png)
        - FANToMとCommon-ToMは、元論文の fine-tuning 結果とおおむね同程度
        - SimpleToM は心的状態と判断の問題、行動の問題の両方でほぼ完ぺきな性能だった
        - BigToM もほとんど同じ
    - 解釈：これらのデータセットについて (1) 他より著しく易しい、または (2) zero-shot の LM が疑似相関を利用している、のどちらかである可能性が高いとしている
- 推奨するベンチマーク作成手順：
    - 設計時：モデルが ToM の推論なしに正解できるヒューリスティックを想定したうえで、ノイズ（無関係な文、同じ課題の複数の言い換え）や敵対的な例（答えられない問題、シナリオの変更）を入れる
    - 構築後：必ず単純な fine-tuning のベースライン（小規模 LM や古典的な統計モデル）を学習させる。予想外に高性能なら、語彙の重なりの調査、解釈可能性の手法、設計の見直しを行う。
- 考察
    - 人間向けに作られたテストの結論を、そのまま LM に当てはめることはできない。モデルを参加者として評価する方法、適応的な評価、シミュレーション環境を使えば、疑似相関を測ってしまうおそれを減らせるとする（＝実際に用いられる条件により近づけるべき）。
    - fine-tuning ベースラインは必要だが十分ではない。性能が高すぎれば問題の兆候だが、高くなくても疑似相関がないとは言えない。
    - LM が ToM を持つかという問いについては、単に心的状態を推論できるかという意味なら「できる」が、似た文脈でも性能が一貫しないことがあるため、ToM の頑健性を測るべきだとする
- 限界
    - 調査が網羅的でない。ケーススタディもデータセット4つ・モデル3種に限られ、他のベースライン（単語埋め込みを特徴量にしたロジスティック回帰など）を加えるべき
    - 検証を行った論文の件数の記述が本文中で揃っていない（要旨では「半数未満」、§4.2 では1件、§6 では構築後に分析を示したのは6件）
